## CPU product path [MEASURED]

Image `openru/protoru:m2` was built with `EXTRA_CMAKE_ARGS="-DENABLE_FFTW=ON -DOPENRU_CUDA=OFF"`
and `MARCH=x86-64-v4` from `docker/lab.env`; FFTW3F was found by CMake. The fork head is
`24af02d8`; the image source is `9bee50c5` (the later commit only adds the unused
`OPENRU_CUDA` option). Build log: `logs/build-m2-cpu.log`.

`make replay-golden OPENRU_TAG=m2` passed all three profiles with **0 differing samples**
over the full DU-slot windows (`baseline` 4000, `b40` 2000, `b100` 800). FFTW + AVX-512 did
not change the CPU golden IQ. Log: `logs/replay-golden-m2-cpu.log`.

below both repeats. The M2 breakdown at the RU is 544 DL U-plane, 33 DL C-plane, 86 UL
C-plane. Artifacts: `docs/reports/smoke-m2-cpu-600s-kpi.json`, `smoke-m2-cpu-600s-late-hist.csv`,
`m2-m1-repeat-1-*` / `m2-m1-repeat-2-*`, and the committed source
`docs/reports/m1-baseline-repeat/` (including the full `r1/r2-du.log` and `r1/r2-ru.log`).

**Host-load confound:** `m2-m1-repeat-1-hostload.txt` and `-2-hostload.txt` record OAI
`nr-uesoftmodem` / `nr-softmodem` processes on cores **32, 37, 46, 50, 55** (inside the
32-55 measurement cpusets) with system load average ~11.8. The two M1-image repeats give
**2.215e-05 / 2.609e-05** (loaded-host; excluded), not `7.094e-06`. The M1 baseline has no
recorded quiet-host check (see `M1.md` caveat). The M2 v4 run has no host-load record:
its **`4.504e-05` is INVALID**, excluded from baselines and gates, and the v4 regression
is **not established**.

**Quiet-host gate (added 2026-11-14):** `make smoke-fh` now runs
`scripts/quiet_host.py` before and every 30 s during the measurement. It records load
average, reserved-core usage, and top foreign processes; any process outside our
du/protoru containers with reserved-core affinity and >5% CPU marks the run **INVALID**
and excludes its numbers. Failed runs are neither PASS nor FAIL.

**Decision:** the 2x2 `{generic DFT, FFTW} x {v3, v4}` was not started. The OAI
containers have since been stopped by the human; with the quiet-host gate in place, two
validated M1 repeats must recover `~7e-06` before the 2x2, the v1 decision, and the
`max_proc_delay` sweep.

## FFTW plan creation [MEASURED]

- Plan creation: `lib/phy/generic_functions/dft_processor_fftw_impl.cpp:104` constructor;
  `:142` `fftwf_plan_dft_1d`; the flag comes from `fftw_config.optimization_flag` (`:133`).
- The lower PHY uses `create_dft_processor_factory_fftw_fast()`
  (`lib/ru/sdr/lower_phy/lower_phy_factory.cpp:20`). The fast factory passes `"measure"`
  with a 5.0 s `plan_creation_timeout_s`
  (`include/ocudu/phy/generic_functions/generic_functions_factories.h:69-76`);
  `generic_functions_factories.cpp:67-68` maps it to `fftw_measure`. The flag is
  **`FFTW_MEASURE`**, not `ESTIMATE`.
- The modulator pool pre-creates the instances plus a base in
  `lib/phy/lower/modulation/modulation_factories.cpp:54-62`; each instance's
  `dft_processor` constructor creates its plan at startup.
  `ofdm_symbol_modulator_pool::modulate` (`ofdm_modulator_pool.h:42-56`) only gets a
  pre-created instance, and `dft_processor_fftw_impl::run()` (`:180`) only calls
  `fftwf_execute`.
- **No plan creation on the per-slot/real-time path**; planning is at lower-PHY
  construction under `mutex_init` (with the `~/.ocudu_fftwisdom` wisdom file). The
  `FFTW_MEASURE` plans can lengthen startup, but they are not the steady-state late
  source.

## CUDA state [MEASURED]/[UNVERIFIED]

- `docker/compose.yml` forwards `EXTRA_CMAKE_ARGS` (default `-DOPENRU_CUDA=OFF`).
- `external/proto-ru/CMakeLists.txt` now declares `OPENRU_CUDA` (default OFF; fork
  `24af02d8`).
- The merged CUDA code (`src/cuda/standalone`) is a **standalone** CMake project that links
  the OCUDU build tree. It is not copied into the Docker build context (`ADD
  external/proto-ru /src`) and is not linked into the OCUDU low-PHY.
- The `ARCH_LOWPHY.md` §8.4 boundary (DL grid+CFO -> `ci16`; UL `ci16` -> grid+PRACH;
  BFP compress/decompress) is not wired. `replay-cuda` / the BFP-byte-identical and
  OFDM `ci16` gate cannot run yet.
- Integrating requires copying/linking the standalone code into the image/fork and adding
  a `cpu|cuda` selection at those three islands, default `cpu`.
