## CPU product path [MEASURED]

Image `openru/protoru:m2` was built with `EXTRA_CMAKE_ARGS="-DENABLE_FFTW=ON -DOPENRU_CUDA=OFF"`
and `MARCH=x86-64-v4` from `docker/lab.env`; FFTW3F was found by CMake. The fork head is
`24af02d8`; the image source is `9bee50c5` (the later commit only adds the unused
`OPENRU_CUDA` option). Build log: `logs/build-m2-cpu.log`.

`make replay-golden OPENRU_TAG=m2` passed all three profiles with **0 differing samples**
over the full DU-slot windows (`baseline` 4000, `b40` 2000, `b100` 800). FFTW + AVX-512 did
not change the CPU golden IQ. Log: `logs/replay-golden-m2-cpu.log`.

600 s null `smoke-fh` (`PROTORU_PROFILE=null`, `OPENRU_TAG=m2`):

| Config | Image MARCH | Gate late | Gate all_pkts | late_frac | drop |
| --- | --- | ---: | ---: | ---: | ---: |
| M1 CPU+null | `m1`, x86-64-v3 | 104 | 14,660,806 | **7.094e-06** | 0 |
| M2 CPU+null | `m2`, x86-64-v4 | 663 | 14,721,756 | **4.504e-05** | 0 |

The M2 KPI reports `warmup_s=0` ("lates not start-clustered"); the late count is spread
over the run, not a startup-only artifact. Breakdown at the RU: 544 DL U-plane, 33 DL
C-plane, 86 UL C-plane. The M1 full-window ratio was 1.488e-05 (219 late); even that is
below the M2 gate-window ratio. Artifacts: `docs/reports/smoke-m2-cpu-600s-kpi.json`,
`smoke-m2-cpu-600s-late-hist.csv`, `logs/smoke-m2-cpu-600s.log` (ignored).

**Interpretation:** the FFTW/`x86-64-v4` CPU build is correctness-clean but regresses the
OFH late ratio by ~6x at the default `max_proc_delay`. The v1 product path is therefore
**not accepted** yet. The next isolation is a 600 s null run with the `m1` (v3) image and
the same profiles, then a `max_proc_delay` sweep (CPU and CUDA) as in the M2 plan.

## CUDA state [MEASURED]/[UNVERIFIED]

- `docker/compose.yml` forwards `EXTRA_CMAKE_ARGS` (default `-DOPENRU_CUDA=OFF`).
- `external/proto-ru/CMakeLists.txt` now declares `OPENRU_CUDA` (default OFF; fork
  `24af02d8`).
- The merged CUDA code (`src/cuda/standalone`) is a **standalone** CMake project that links
  the OCUDU build tree. It is not copied into the Docker build context (`ADD
  external/proto-ru /src`) and is not linked into the OCUDU low-PHY.
- The `ARCH_LOWPHY.md` §8.4 boundary (DL grid+CFO -> `ci16`; UL `ci16` -> grid+PRACH;
  BFP compress/decompress) is not wired. `replay-cuda` / the BFP-byte-identical and
  OFDM `ci16` gate cannot run yet.
- Integrating requires copying/linking the standalone code into the image/fork and adding
  a `cpu|cuda` selection at those three islands, default `cpu`.
